## Board spike (2026-10-25)
- Board 2: **The lesson lint does not check `col` expressions yet.** A wrong name there shows only in the browser. (Plane marks are linted since U4.) A `col` also cannot read an earlier `col`'s key on the same table ("unknown name" in the browser); the perceptron lesson writes the score's full expression again in its `ŷ` column.
- Board 4: **A row calc writes `x_i`, not `x_1`.** `d_1 = x_i − x̄` for row 0 reads oddly; the row's index should replace `i` in the symbol.
- Board 6: **The check audits a run only at its two ends and at the click stops.** The middle frames (3 to 10 of the gallery's 12) were swept once by hand in U4, all clean, but `check.py` does not do it. A sweep of every frame for a run of 20 or fewer would close this.
- Board 7: **A run's length is typed in the YAML (`run: 12`) and nothing ties it to the data.** If `make_data.py` writes 11 frames, `at(w0_trace, 11)` gives nothing: a point then warns "outside the box", but a line just drops out of the picture and only its legend says so. The lint could compare `run` with the length of each list read through `at(…, t)`.
- Board 8: **`when:` works on plane marks only.** A chart mark or a worked line cannot yet appear for some frames and not others.
- Board 10: **The symbol ledger matches TeX as text.** A symbol written `d_{1}` in prose and `d_1` under `symbols` is not seen, so its "symbol before number" error is missed. A KaTeX parse of both sides would close it.
- Board 13: **A lesson's `home:` key is not checked.** `board.md` sets the convention (`data.json` holds `"home": {name, provenance}` copied from the home file), but no lint ties `home: cells` to that block yet. U8 is its first real use; lint it after.
- Board 14: **`home.py` clips negative marker draws to 0.0**, so a few cells read exactly 0.0 (as real cytometry exports often do). If a board looks odd with a bare 0.0, pick another seed rather than change the recipe (a recipe change needs a version bump in `home.py`).
- Board 17: **A board chart in the picture column is short** (about 110px of plot in a 480px column) because the deck chart keeps its aspect from the width. Readable, but a run or what-if chart would teach better taller.
- Board 18: **Plane points coloured `by:` a field show one legend entry per value, even when two values share a colour and only one has a label.** The thymocyte tease showed bare "SP8" and "DP" entries; it now colours by `y` (two values). Entries with the same colour and no label could be merged.
- Board 21: **`{{…}}` inside `$…$` in a `note` is not filled in**; KaTeX then fails to parse it. Put the number outside the maths, or in a worked line.
- Board 22: **A worked line shows its inputs with extra digits** (4.4747², 2.7268²). The deck gives inputs up to 2 extra digits so a line adds up by hand (`design.md`); on a board the inputs then look noisier than the answer.
- Board 24: **The deck's notation chip (`x_ij` = …) can spill out of a narrow `ops` card on a board.** `notation: false` hides it; the board audit could warn first.
- Board 25: **The PCA `verify_data.py` files were written by the same model as `make_data.py`** (plan KTD21 asked for a Grok worker from a prose spec). They use numpy's `eigh` and `cov` against pure-Python power iteration and closed forms, so the code paths are separate, but the author is not. An independent rewrite would close it.
